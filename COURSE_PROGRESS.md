# Текущая точка

**Текущий практический проект:** калькулятор стоимости заказа использует пакет `order_app`; история заказов хранится построчно в JSON Lines-файле `order_app/orders/order.jsonl`.

**Что сделано на практике:**
- функции `get_num()`, `get_price()`, `save_order()`;
- сохранение заказов построчно через `json.dump()` в режиме добавления и чтение через `json.loads()`;
- получение последнего заказа и сводное чтение истории JSON Lines по строкам;
- проверка истории без изменения файла: прочитаны 15 непустых JSONL-записей; 7 соответствуют текущей модели, 8 отклоняются как старые данные или намеренно испорченные тестовые записи.
- модели `Product` и `Order` описаны через `TypedDict`; добавлены функции базовой runtime-проверки строк Decimal, товара и заказа.
- повтор ввода при `ValueError`;
- проверка положительного количества и цены;
- подсчёт общей стоимости в цикле;
- создание папки `orders` через `Path.mkdir()`;
- запись результата в `order.txt`;
- обработка `OSError` при сохранении;
- проверка типа `total` через `isinstance()`, исключение `bool` из допустимых значений;
- исправление логического условия с `not` и `or`;
- проверка конечности цены и суммы через `isfinite()`: `nan` и `inf` отклоняются; пользователь проверил работу программы;
- ввод товаров и расчёт заказа выполняются через `main.py` и `order_app.tools`; запись JSONL и чтение истории находятся в `order_app.storage`.

**Текущая тема:** JSON Lines и проверка данных заказа — проверка структуры и сумм, пропуск пустых строк и поиск последнего корректного заказа применены на практике; навык закрепляется в проекте бота.

**Следующий шаг:** перейти к Telegram-боту воронки продаж — определить продукт, аудиторию и этапы общения, затем изучить базовую структуру бота и обработку сообщений.
